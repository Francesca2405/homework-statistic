Homework 1: Public-Key Cryptography in Ethereum

Statistical Analysis and Cryptographic Primitives Exploration

1. Mathematical Background

Public-key cryptography in Ethereum is based on Elliptic Curve Cryptography (ECC) with the secp256k1 curve. To see the mechanics without 256-bit parameters, this homework uses a toy curve over a finite field.

Curve: y² ≡ x³ + 7 (mod 17)
Base point: G = (1, 5)

G is fixed, as in the real protocol: the only variable is the private key k. The curve has 18 points (17 affine + the point at infinity ∞), but G generates only a subgroup whose order n is computed by the script (the smallest n with nG = ∞). Consequently kG is periodic in k: k and k + n give the same public key, and k = n gives ∞, which is not a valid key.

4. Theoretical Discussion

The measurements above separate the properties of an elliptic-curve one-way function from those of a cryptographic hash function.

1. Uniformity and bit distribution

Hash functions must look uniformly random: every output bit is 0 or 1 with probability 1/2. ECC need not: over this tiny field the coordinates are values in 0…16 stored in 5 bits, so the top bit is almost always 0, and only the points of the subgroup ever appear. What matters for ECC is that k ↦ kG is injective over one period (each point appears exactly once) and that inverting it requires solving the ECDLP.

2. Avalanche effect

Hash functions demand that flipping one input bit flips about 50% of the output bits. The Hamming-distance measurements above show that ECC points do not behave this way, and it is not required: security rests on the intractability of the ECDLP, not on bit diffusion.

3. Algebraic structure: wanted in ECC, forbidden in hashes

Scalar multiplication is a group homomorphism: (k₁+k₂)G = k₁G + k₂G, as verified exhaustively above. This structure makes signatures, key derivation and ECDH possible, but it would be a fatal weakness in a hash, which must have no exploitable relation between related inputs. The linear correlation between k and the coordinates should also be read in this light: for a real curve it is negligible, here it is only a small-sample effect.

4. Where they meet in Ethereum

An Ethereum address is the last 20 bytes of keccak256 applied to the public key: the elliptic-curve one-way function (private → public key) and the hash (public key → address) are used together, each for the property it is designed to have.
