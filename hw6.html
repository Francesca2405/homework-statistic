Homework 6: Advanced Integration

Riemann vs Lebesgue Methodologies & Numerical Normal CDF

1. Riemann and Lebesgue Integration Methods

Theoretical Discussion & Methodological Comparison

1. Convergence and Agreement on Standard Functions

The Riemann Integral approaches the problem by partitioning the domain (the x-axis) into infinitesimally small subintervals, computing the area as a sum of vertical slices (e.g., using the Midpoint rule). The Lebesgue Integral, conversely, partitions the range (the y-axis) into subsets and evaluates the exact analytical measure of the domain preimages where the function falls into those subsets. This is mathematically expressed via the "layer-cake" formula: ∫f = ∫ μ{x: f(x) > t} dt.
For standard, Riemann-integrable functions (such as x², sin(x), or piecewise step functions), both approaches converge securely to the exact same theoretical value. Computationally, however, the numerical Riemann sum is highly efficient, resolving in O(N) time. Implementing a "genuine" numerical Lebesgue integral requires analytical knowledge of the preimages (or root-finding algorithms like Binary Search for functions like sinc(x)), making it computationally heavier but theoretically more robust.

2. Pathological Behavior: Where the Methods Diverge

The philosophical divergence between the two integrals becomes evident when evaluating pathological functions characterized by dense discontinuities.

  • The Dirichlet Function (1 on Rationals, 0 on Irrationals): This is the classic example of a Riemann-non-integrable function. Its upper and lower Darboux sums are perpetually stuck at 1 and 0, regardless of the partition size. However, the Lebesgue approach resolves this trivially: since the set of rational numbers is countably infinite, its Lebesgue measure is precisely 0. Thus, the integral evaluates exactly to 0.
  • Thomae's "Popcorn" Function (1/q for x = p/q): Theoretically, Thomae's function is Riemann integrable and evaluates to 0, because its discontinuities are countable and have measure zero. However, numerical Riemann integration fails spectacularly if implemented naively. Because every floating-point number in a computer is rational, a naive Riemann sum evaluating f(i/N) will artificially hit rational high-density fractions, producing an artifact value strictly greater than 0. To properly emulate its convergence, our algorithm computes f = gcd(i,N)/N, forcing the sum to converge to 0 at a slow rate of τ(N)/N. The Lebesgue approach, relying purely on the analytical measure of the level sets (which is 0 for any t > 0), bypasses these floating-point artifacts entirely, returning 0 instantly.

2. Numerical Computation of the Normal CDF

Liouville's Theorem and The Error Function (erf)

To compute the Cumulative Distribution Function (CDF) of the standard normal distribution, denoted as Φ(z), we must evaluate the integral of the Gaussian probability density function:

Φ(z) = ∫-∞z (1 / √(2π)) e-t²/2 dt

Mathematical Impossibility (Liouville's Theorem)

Why can't we just find a simple algebraic formula for this integral? Liouville's Theorem states that if an integral of the form ∫ f(x)e^{g(x)} dx (where f and g are rational functions) has an elementary antiderivative, that antiderivative must be of the form R(x)e^{g(x)}, where R is a rational function.
By differentiating this supposed antiderivative, we get: R'(x) + g'(x)R(x) = f(x). Substituting the Gaussian terms (where g(x) = -x²/2 and f(x) = 1), the equation simplifies to:

R'(x) - x R(x) = 1

This differential equation has no solution in the realm of rational functions. If R(x) were a polynomial of degree n, the left side would have a highest degree of n+1, which can never equal a constant (degree 0). Furthermore, if R(x) had a pole (a denominator), the derivative R'(x) would increase the order of that pole, making it impossible for the terms to cancel out and yield 1. Therefore, no elementary antiderivative exists.

The Role of the Error Function

To provide an exact analytical representation, mathematicians defined the Error Function (erf), establishing the exact relationship: Φ(z) = ½[1 + erf(z/√2)]. However, this is just an analytical label. Because the underlying integral remains non-elementary, any practical software implementation evaluating erf() must still rely on numerical approximation techniques (like series expansions or rational approximations) under the hood.

Analysis of Numerical Approaches & Tail Accuracy

  • Numerical Integration (Simpson's 1/3 Rule): Splitting the area into parabolic arcs yields a stable, highly accurate result with an error convergence of O(h⁴). A crucial implementation detail concerns the tails: calculating deep negative tails (e.g., z = -8) by subtracting the integral from 0.5 (i.e., 0.5 - ∫) destroys relative accuracy, introducing errors up to 16%. To achieve 15-digit precision on the tails, the integration must be executed directly from a deep lower bound (e.g., -38) up to z.
  • Alternating Taylor Series: Expanding the exponential term yields an alternating series. While incredibly fast for small values of |z|, it suffers from catastrophic cancellation at larger values (e.g., |z| ≥ 6). The intermediate terms become astronomically large before the factorial denominators can pull them down; adding and subtracting these huge floats in 64-bit precision destroys all significant digits, leading to massive truncation errors or even mathematically impossible negative probabilities.
  • Positive-Term Series & Asymptotic Tails: To bypass cancellation near the mean, we can rewrite the expansion into a series containing exclusively positive terms: Φ(z) = 0.5 + (1/√(2π))e^{-z²/2} Σ z^{2k+1}/(1·3·5...(2k+1)). However, for extremely deep negative tails (z ≤ -4), converting this back to CDF still involves a 0.5 - 0.5 operation that loses accuracy. The ultimate solution for deep tails is employing the Asymptotic Expansion (a continued fraction approach: 1 - 1/z² + 3/z⁴...), ensuring perfect relative accuracy without floating-point cancellation.
